The hreflang attribute is allowed to be a `string` or `array` in this version of the spec. Depending on the result of [[LINKSET-MEDIA-TYPES]] the values of `hrefLang` can be restricted to `array` only.

Link relations can be used to describe relations such as to other Things (e.g., a Switch Thing controls a Lamp Thing), to a specific kind of Thing Models (e.g., a Thing Description is an instance of a specific Thing Model), or to further documentations information (e.g., device manual of a Thing). It is recommended to reuse existing and established [Link Relation definitions from IANA.](https://www.iana.org/assignments/link-relations) The link relation types follow Web Linking [RFC8288 Section 2.1], meaning:
  • Relation types *MUST* be compared as strings using case-insensitive comparison. (If they are serialized in a different format they are to be converted to URIs.) Because the general TD Information Model is strictly case-sensitive, this rule act as an explicit exception for link relations. TD Consumers should be permissive and handle mixed-case relation types gracefully.
  • All-lowercase URIs *SHOULD* be used for extension relation types. Note that while this is the recommended practice for newly defined extensions, some existing WoT-specific relation types in the table below (such as `controlledBy`) have historically used mixed casing. Due to the case-insensitive comparison requirement, these legacy mixed-case types remain fully valid and interoperable.
